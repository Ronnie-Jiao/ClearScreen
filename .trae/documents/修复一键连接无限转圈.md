# 修复「一键连接」无限转圈

## Context

用户反馈：在「服务与权限」页点 ADB 开关（一键连接）后一直转圈，停在「正在连接」，拿不到结果也没有明确结束。

已读代码确认，转圈不是单一原因，而是整条链路**没有任何阶段超时**，且前端把某些中间态当成永久 pending：

| 位置 | 问题 |
| --- | --- |
| `ClearScreenAdbPairingHelper.kt` | 状态机 `waiting-code → pairing → waiting-port → connecting` 无 deadline。配对弹窗读不到配对码就永远停在 `waiting-code`；配对成功后若设置页不再发无障碍事件，就永远停在 `waiting-port` |
| `ClearScreenAccessibilityService.kt` L253-260 | 只在收到 `com.android.settings` 事件后延时 60/300/900ms 扫描 3 次，之后不再扫描；端口出现后没有新事件就永远读不到 |
| `ServicePermissionsScreen.tsx` L63, L163-164, L172 | `AUTO_PAIR_STAGES` 全部当成 `adbPending=true`（永久转圈）；`adbRestoring`（paired + reconnectRequested + idle）可能永久为真，导致转圈且整行 `disabled`，连"再点一次重试"的出口都没有 |
| `ClearScreenNative.ts` L420-443 | 所有 ADB 原生 Promise 没有超时；原生共享单线程 `executor` 被长任务占用时，Promise 可能长期不返回，`adbBusy` 永远不清空 |

设备取证（小米 22101317C，`[DEVICE-ID]`，当前 1.0.92/98）：
- `settings get secure enabled_accessibility_services` 只有 `com.linkpilot.android/.RemoteAccessibilityService`，**净屏无障碍服务未启用** → 目前自动配对必然读不到配对码；
- `settings get global adb_wifi_enabled` = 0（无线调试关闭）；
- 设备处于锁屏（`isKeyguardShowing=true`），`logcat` 无净屏 ADB 阶段日志（配对链路本身不打日志），需解锁后复现取证。

目标：任何一步拿不到结果，都在固定时间内结束转圈，给出可读原因和可重试入口。

## 改动

### 1. 原生：阶段超时 + 持续扫描

**`android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenAdbPairingHelper.kt`**
- 记录 `stageSince`（`SystemClock.elapsedRealtime()`），每次切换 stage 时更新。
- 新增 `fun tick()`，由无障碍服务周期调用：
  - `waiting-code` 超过 120s → 失败：「没有读到配对码，请重新点按开关，在系统设置里打开「无线调试」并点「使用配对码配对设备」」
  - `pairing` 超过 60s / `waiting-port` 超过 60s / `connecting` 超过 90s → 失败，文案分别对应"配对没完成""没有读到连接端口""连接没有完成"。
  - 超时统一走内部 `fail(reason)`：`stageName="failed"`、`statusText=reason`、`active=false`、清空 host/port/key，**不打印配对码或端口**。
- 仅在 stage 变化时 `Log.i("ClearScreenAdb", "pair stage=...")`，用于真机取证（不含敏感值）。

**`android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenAccessibilityService.kt`**
- `adbPairingScan` 改为自循环：只要 `ClearScreenAdbPairingHelper.isActive()` 且服务未销毁，扫描后 `handler.postDelayed(adbPairingScan, 700L)`；每次先调 `tick()`，再按当前 root 调 `onSettingsWindow`（root 不是 settings 也要 tick，保证超时生效）。
- 事件触发的三次延时扫描保留（更快的首读），重复 post 前先 `removeCallbacks`。

### 2. 前端：去掉永久 pending，加超时与失败出口

**`src/native/ClearScreenNative.ts`**
- 加一个小的 `withTimeout(promise, ms, message)`。
- `getAdbAccessStatus` 6s、`startAdbAutoPair`/`stopAdbAutoPair` 15s、`autoConnectAdb`/`connectAdb`/`pairAdb` 45s；超时抛可读错误，不让 UI 永久等 Promise。

**`src/screens/ServicePermissionsScreen.tsx`**
- 删除 `adbRestoring` 对 `adbPending` / `disabled` 的影响（后台自动恢复由 `state==='connecting'` 体现，不再永久占用 pending）。
- `autoPairStage==='failed'` 时：
  - `adbStateText='连接失败'`；
  - ADB 行下方显示一行原因（`autoPairMessage || message`），并给「重试连接」按钮（`toggleAdb()`）；
  - 首次失败弹一次弹窗（`tone:'error'`，按钮「重试」「关闭」），用 ref 去重。
- 前端看门狗：`adbPending` 连续超过 150s 仍未结束 → 清 `adbBusy`、强制刷新状态，弹「连接没有完成」+ 原因 + 「重试连接」。
- 轮询间隔保持（auto 阶段 1.2s）。

## 真机验证（小米 22101317C / [DEVICE-ID]）

1. 请用户解锁手机（锁屏有数字密码，adb 无法绕过）。
2. 装前 `dumpsys package ... lastUpdateTime` 确认无并行安装；`adb install -r --no-streaming`（不卸载、不 `pm clear`）。
3. 用 `settings put secure enabled_accessibility_services` 在保留 `com.linkpilot.android` 的前提下追加净屏服务，并 `accessibility_enabled=1`。
4. **失败态**：保持无线调试关闭（`adb_wifi_enabled=0`），点 ADB 开关 → 等待超时 → 截图，确认转圈结束、显示原因与「重试连接」，`logcat -s ClearScreenAdb` 能看到停在哪个 stage 后 failed。
5. **成功态**：打开开发者选项→无线调试→使用配对码配对设备，回到净屏点开关，等待自动配对 → 截图「已连接」，`dumpsys`/原生 `id` 结果确认 `uid=2000`。
6. 截图存 `screenshots/2026-11-09-一键连接-失败.png`、`screenshots/2026-11-09-一键连接-成功.png`，回复中用 `computer://` 链接给出。

## 风险与边界
- 只动 ADB 开关这一条链路，保留另一窗口在 `ServicePermissionsScreen.tsx`、`ClearScreenAccessibilityService.kt` 等文件的未提交改动（在其基础上编辑，不 reset/覆盖）。
- 无障碍服务当前未启用；验证时临时启用，不改动 `com.linkpilot.android` 的授权。
