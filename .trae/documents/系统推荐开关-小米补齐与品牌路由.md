# 「系统推荐开关」页：小米补齐 + 品牌路由 + 状态文案改造

## Context

用户反馈净屏「系统推荐开关」页在 vivo 与小米（HyperOS）差太多：vivo 有 11 个可切换项，小米只有 1 个「个性化广告推荐」，另外「广告与隐私 / 资讯与推荐 / 应用商店推广」三行只显示路径文字、需要用户自己照着找。本次只改这一页及其原生能力（「授权通道」页由并行窗口负责，不动）。

目标：
1. 小米侧补齐到与 vivo 同量级的开关列表（11 项）；能代点的代点，能跳页的跳页并读出状态，做不到的显式给出原因，不静默消失。
2. 开关登记与跳转落点按厂商集中登记（vivo/iQOO、小米 HyperOS/MIUI、华为、荣耀、OPPO/一加/realme、三星 + 通用兜底），不写死在 vivo 分支。
3. 「手动去设置」三行整行可点，直落品牌对应页面，逐级降级并给出明确提示。
4. 列表状态词从「未处理 · 需无障碍 / 直接改写」改为用户能看懂的作用说明。

## 现状关键事实（已在小米 22101317C / HyperOS 2 上 `am start` 验证）

| 落点 | Component | 结果 |
|---|---|---|
| 广告服务 | `com.android.settings/.ad.AdServiceSettings` | 可启动，含「个性化广告推荐」 |
| 应用商店隐私 | `com.xiaomi.market/.business_ui.settings.recommend.RecommendSettingsFragmentActivity` | 可启动，含「个性化服务」 |
| 全局搜索设置 | `com.android.quicksearchbox/.preferences.SearchSettingsPreferenceActivity` | 可启动；其子页 `OtherSettingsPreferenceActivity` 未导出，第三方不可直达 |
| 桌面设置 | `com.miui.home/.settings.MiuiHomeSettingActivity` | 可启动，含「智能助理」 |
| 浏览器设置 | `com.android.browser/.BrowserSettingsActivity` | 可启动；「宫格位推送」在子页「主页设置」 |
| 负一屏 | `com.miui.home/.settings.LauncherPersonalAssistantSettingActivity` | 受 `miui.permission.USE_INTERNAL_GENERAL_API` 保护，不可达 |

小米设置表（secure/system/global）中没有可读写的 personalized/recommend 键，因此小米全部走「代点」或「跳页」，不做伪 direct。

## 改动方案

### 1. 新增 `ClearScreenRecommendCatalog.kt`（集中登记表）

路径：`android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenRecommendCatalog.kt`

- 定义路由常量：`ROUTE_AD_PRIVACY`、`ROUTE_NEWS`、`ROUTE_STORE`、`ROUTE_XIAOMI_SEARCH`、`ROUTE_XIAOMI_LAUNCHER`、`ROUTE_XIAOMI_BROWSER`、`ROUTE_HOME_SCREEN`。
- `fun targets(context): List<Target>`：按 `ClearScreenOemProfile.current()` 取厂商列表 + Android 13+ Google Play 服务可用时的 `androidAdPrivacy` 三项（逻辑从 `ClearScreenUiCleanup.targets` 平移）。
- 各厂商列表从 `ClearScreenUiCleanup.kt` 现有 `vivo/huawei/honor/oppo/oneplus/motorola` 常量平移过来，小米替换为新列表。
- 缺省厂商返回空列表（页面已有空状态 + 手动入口），保持现有行为。
- `ClearScreenUiCleanup.targets(context)` 改为委托调用本对象，`CleanupController` / `NativeModule` 调用点无需改动。

### 2. 扩展开关模型 `ClearScreenUiCleanup.Target`

追加带默认值的字段（不破坏现有调用）：
- `effect: String = ""`：用户语言的作用说明，如「关掉后系统应用不再按你的兴趣推广告」。
- `support: String = "assisted"`：`assisted`（无障碍代点）/ `manual`（只能跳页手动关）/ `unreachable`（系统不开放）。
- `navigate: String? = null`：跳转路由键，代点开始前由 `startUiCleanup` 使用。
- `reason: String? = null`：`manual` / `unreachable` 的明确原因。

### 3. 小米登记项（11 项）

| id | 标题 | page | support | navigate / reason |
|---|---|---|---|---|
| `xiaomi.system.personalizedAds` | 个性化广告推荐 | 广告服务 | assisted | `settings.adPrivacy` |
| `xiaomi.store.personal` | 个性化服务 | 隐私 | assisted | `store.home` |
| `xiaomi.launcher.assistant` | 智能助理（负一屏总开关） | 桌面设置 | assisted | `xiaomi.launcher` |
| `xiaomi.search.hint` | 搜索提示词 | 搜索设置 | manual | `xiaomi.search`；需点「首页展示模块」 |
| `xiaomi.search.app` | 应用推荐 | 搜索设置 | manual | 同上 |
| `xiaomi.search.history` | 搜索历史 | 搜索设置 | manual | 同上 |
| `xiaomi.browser.grid` | 宫格位推送 | 主页设置 | manual | `xiaomi.browser`；需点「主页设置」 |
| `xiaomi.assistant.news` | 资讯推荐 | 个性化推荐 | unreachable | 负一屏设置受系统保护 |
| `xiaomi.assistant.services` | 服务推荐 | 个性化推荐 | unreachable | 同上 |
| `xiaomi.assistant.content` | 内容精选 | 内容精选 | unreachable | 同上 |
| `xiaomi.assistant.hot` | 热点资讯 | 热点资讯 | unreachable | 同上 |

其余厂商项同步补 `effect` 文案与 `navigate`（复用现有 category/entry 语义）。

### 4. 新增 `ClearScreenRecommendRoutes.kt`（集中路由表）

路径同上目录。结构：

```kotlin
internal object ClearScreenRecommendRoutes {
  data class Entry(val level: String, val intent: Intent, val hint: String? = null)
  fun candidates(route: String, context: Context, family: ClearScreenOemProfile): List<Entry>
  fun appDetails(context: Context): Intent
}
```

- level：`vendor`（厂商专有页）/ `system`（系统标准 Intent）/ `appDetails`。
- 小米：`settings.adPrivacy` → `AdServiceSettings`（含 `Settings$AdServiceSettingsActivity` 备选）；`store.home` → 应用商店隐私页 → 商店启动 Intent；`xiaomi.search` → quicksearchbox 搜索设置；`xiaomi.launcher` → `MiuiHomeSettingActivity`；`xiaomi.browser` → `BrowserSettingsActivity`。
- vivo：沿用现有 `VIVO_SUB_SETTINGS_ACTION` + fragment、`MORE_SECURITY_PRIVACY` 候选。
- 华为/荣耀/OPPO/一加/三星：先试已登记的品牌候选（无已证实候选的只登记标准 Intent），再 `ACTION_PRIVACY_SETTINGS` / `ACTION_SETTINGS`。
- 每个 `Entry` 可带 `hint`，用于「只到上级页面」时告诉用户下一步点哪。

### 5. `ClearScreenSettingsNavigator` 增加统一入口

- 新增 `data class RouteResult(val level: String, val component: String, val hint: String?)`。
- `fun openRecommendRoute(route: String): RouteResult`：按 candidates 顺序 `canOpen` 预检 → `startActivity`，捕获 `ActivityNotFoundException` / `RuntimeException` 后继续下一级；全部失败时落应用信息页并带提示；连应用信息页都打不开才抛异常。
- `component` 返回实际落地的 `ComponentName.flattenToShortString()` 或 action，供真机验收记录。
- 现有 `openSystemAdPrivacySettings` 保留，内部改为走 `settings.adPrivacy`，避免两套逻辑。

### 6. `ClearScreenNativeModule`

- 新增 `@ReactMethod fun openRecommendRoute(route: String, promise: Promise)`，返回 `{level, component, hint}`。
- `startUiCleanup` 的跳转改为：`target.navigate != null` → `settingsNavigator.openRecommendRoute(target.navigate)`；否则保留现有 category/entry 分支（兼容 vivo home/browser 入口）。
- `getUiCleanupTargets` 的 `WritableMap` 追加 `effect`、`support`、`reason`、`navigate`。

### 7. 前端 `src/native/ClearScreenNative.ts`

- `UiCleanupTarget` 增加 `effect: string; support: 'assisted' | 'manual' | 'unreachable'; reason?: string | null; navigate?: string | null`。
- 新增 `openRecommendRoute(route): Promise<{ level: 'vendor' | 'system' | 'appDetails'; component: string; hint: string | null }>`。

### 8. `src/screens/SystemRecommendScreen.tsx`

- 删除 `guide()` 与 `paths`（长路径文字不再作为主要内容）。
- 「手动去设置」三行改为整行可点，副标题换成作用说明：
  - 广告与隐私：关掉后系统应用和浏览器不再按你的兴趣推广告
  - 资讯与推荐：关掉后桌面搜索、浏览器不再推热搜和资讯卡片
  - 应用商店推广：关掉后应用商店不再推个性化推荐和开屏推广
  - 点击调 `openRecommendRoute`；`level === 'appDetails'` 或返回 `hint` 时弹窗说明下一步点哪。
- 开关行文案：
  - 第二行显示 `effect`；已知状态时前缀「已关闭 · / 仍开着 ·」，未知不显示内部状态词。
  - `support === 'manual'`：整行可点 + Chevron，点击跳 `navigate` 并弹 `reason` + 下一步提示，不显示 Toggle。
  - `support === 'unreachable'`：只显示 `reason`，无 Toggle、无 Chevron。
  - `support === 'assisted' | 'direct'`：保留 Toggle 与现有代点/直写流程。
- 保留空状态与无障碍未开启提示，文案改为结果导向（「开启后才能自动帮你关这些开关」）。

## 验证

1. `npx tsc --noEmit`。
2. 确认无残留 Gradle 锁/守护进程后 `gradlew :app:assembleRelease`。
3. 先 `adb devices` 确认无并行窗口正在安装，再 `adb -s [DEVICE-ID] install -r`（不卸载、不 `pm clear`）。
4. 真机逐项验收：打开「系统推荐开关」页，对三行与每个可点开关行逐行点击，每次点击后 `adb shell dumpsys activity activities | grep -E "mResumedActivity"` 记录实际 Activity，并截图。
5. 代点项（个性化广告推荐 / 个性化服务 / 智能助理）验证开关能切换且状态回读正确；manual/unreachable 项核对提示文案与原因。
6. 输出「系统推荐开关」页整页截图 + 每行实际落地 Activity 清单；做不到直达的项说明卡在哪一级。
