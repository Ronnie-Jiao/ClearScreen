# 净屏｜通用广告识别架构 v3

> 目标是让新 App、新广告 SDK、新尺寸和新倒计时能通过**通用特征**得到合理处理，而不是每遇到一张新广告就为某个包名新增 if 分支。本文件同时区分**本次已经写入的代码**与**下一阶段的设计**。

## P0 安全屏障：时间类提醒优先（已加入运行时代码）

任何真正的闹钟、倒计时、计时器、秒表、日程提醒均**不是广告**，绝不允许因界面中存在「跳过 / 关闭 / ×」而自动操作。实现参见 `ProtectedUiPolicy.kt`：
- 优先屏蔽已知及语义匹配的时钟、日历、提醒 App 包名；
- 通过窗口类名、可见界面文字、控件资源 ID 识别陌生 App 中的闹钟 / 倒计时 / 提醒界面；
- 保护判断在广告匹配评分之前进行，命中即**不执行任何点击**，用户的单 App 自动跳过开关也不能覆盖；
- 节点点击前、手势执行前再次检查当前前台窗口；
- 发生歧义时**宁可漏掉广告，也不关闭用户的提醒**。

广告倒计时「3 跳过」仍可作为候选，但纯数字倒计时不是广告证据。完全不可读的第三方全屏计时器仍需真机验证，不能承诺绝对零误判。新增 `ProtectedUiPolicyTest.kt` 作为强制回归测试。

## 1. 本次已写入代码（PR #1）

| 层级 | 实现 | 解决的问题 |
| --- | --- | --- |
| A. 语义词法层 | `AdSemanticRules.kt` | 分别解析文字、无障碍描述、资源 ID，支持中英文广告、跳过、倒计时、标准关闭形态；排除跳过引导/权限相关的控件命名 |
| B. 布局层 | `AdGeometryRules.kt` | 不用绝对坐标；兼容右上角开屏按钮、位于弹窗右上角或漂浮在广告卡片之外的 × |
| C. 语境验证层 | Service 的祖先、邻近节点、同一广告卡片上下文 | 只有广告证据或多个独立商业促销特征支撑时，才允许把普通的“关闭/×”当广告 |
| D. 安全执行层 | 节点点击优先，严格约束手势点击 | 避免点击全屏父容器、不在后台 App/系统权限页面误点 |
| E. 时间层 | 窗口延迟复查、节流、倒计时稳定指纹、尝试预算 | 解决迟加载、倒计时变化、短时间重复点击 |
| F. 回归测试层 | `AdSemanticRulesTest.kt`、`AdGeometryRulesTest.kt` | 正向覆盖常见广告 UI，反向覆盖普通关闭、教程、设置、全屏按钮 |

**注意：** 上述语义与几何单元测试不等于整个 Android App 已经编译并真机通过。最终是否可点击还受无障碍节点是否可访问、Android 系统授权及厂商 ROM 行为制约。

## 2. 完整检测流水线（目标）

```text
窗口事件
  ↓
排除：系统敏感窗口 / 净屏自己 / 用户停用 App
  ↓
分阶段扫描：即时 + 延迟 220/600/1200ms
  ↓
无障碍节点语义 + 资源 ID
  ↓
判断：广告语境 + 相对布局 + 关闭/跳过动作关系
  ↓
风险判定：敏感界面 / 容器过大 / 证据不足
  ├─ 高置信 → ACTION_CLICK（必要时受限手势）
  ├─ 中置信 → 先观察，等待下一次窗口变化，不盲点
  └─ 无可用节点 → 记录匿名类型（需用户明确打开诊断）
  ↓
去重 / 限次 / 结果复查
  ↓
本地记录：已执行 / 可验证完成 / 失败
```

## 3. 下一步 P1：真正可扩展的规则系统

**这部分尚未写入运行时，不要在 UI 里宣传“在线规则更新已上线”。**

将动态规则独立于 Kotlin 业务代码，定义一份**本地规则包**，例如：

```json
{
  "schema": 1,
  "id": "generic-ads",
  "version": "2026.10",
  "rules": [
    {
      "id": "generic.splash.countdown",
      "kind": "splash",
      "texts": ["^\\d{1,2}(秒|s)?跳过", "^跳过\\d{1,2}"],
      "requires": ["compact-control", "near-top-corner"],
      "action": "click"
    }
  ]
}
```

约束：
- 规则描述**目标节点、条件、动作、置信度阈值**，不允许下载和执行任意代码；
- 多 App 的通用规则排第一层，少数顽固广告 SDK 的资源 ID 规则排第二层，**个别 App 的专属规则最后才使用**；
- 支持离线内置规则、版本号、校验、回滚；将来有可信更新源时，再允许用户手动或自动更新；
- 远程更新必须有**可信签名验证、来源审查、规则安全校验和撤回机制**；不能把陌生人上传的规则自动赋予点击权限；
- 所有规则必须经过负面样本（普通界面、登录、付款、权限设置）回归才能发布。

## 4. 下一步 P1：用户不必每次发截图的诊断方式

一个简单的诊断功能，比不停发送原始截图更有长期价值：

1. 设置 → 高级 → **识别诊断**（默认关闭，用户主动开启，例如仅运行 10 分钟）。
2. 记录**目标应用包名、窗口类型、控件类型、可点击状态、相对坐标、脱敏后的资源 ID 与规则命中原因**，不要自动保存页面文本、验证码、聊天或完整截图。
3. 本地提示：“发现疑似广告弹窗，但没有安全的关闭控件”，给出“复制脱敏报告 / 停用此 App 自动跳过”。
4. 用户自己确认并提交脱敏报告；未来可用它自动聚类「未暴露节点」「控件不 clickable」「语义没命中」「关闭后仍存在」等失效类型。
5. 若用户不主动提供样本，只能持续提升通用规则对已知类别的覆盖，**无法保证发现所有未来出现的全新图像广告形式**。

## 5. 下一步 P2：可选本地图像识别兜底

若某个广告通过 Canvas、SurfaceView 或图片绘制，Android 无障碍节点树里压根没有“跳过/关闭”控件，增加关键词并不能解决。

可选路线：
- 用户明确授权的屏幕内容获取（遵守 Android 版本约束，不暗中截屏）；
- 使用手机本地 OCR / 轻量视觉模型识别“跳过”、倒计时或关闭图标；
- 视觉结果必须和窗口上下文、位置、时序交叉验证；**不能单凭看见一个 X 就点击**；
- 隐私默认本地处理、不上传图像、不采集敏感页面；支付、登录、权限等页面应直接排除；
- 需要测实际耗电、延迟、误触和系统授权体验，未通过测试时不上线。

**不是必须上云 AI**。这类任务通常先考虑本地规则 + 有选择的本地 OCR；持续全屏图像分析的电量和隐私成本都更高。

## 6. 验收标准

- 编译：`cd android && ./gradlew :app:testDebugUnitTest` 及 `./gradlew :app:assembleDebug` 成功（Windows 使用 `gradlew.bat`）。
- 每种典型场景至少 10 次：开屏倒计时、居中浮层、非标准关闭 X、WebView、无广告正常启动。
- 负面场景至少 10 次：权限对话框、隐私协议、新手引导、登录、支付、正常设置的关闭按钮。
- 检测性能：频繁界面刷新下无持续 CPU 峰值，不重复打断前台操作。
- 正确性：统计不把单纯接受点击操作认作广告肯定已经消失。
- 安全性：**以误点率为第一约束**，不为了多跳过几次广告而增加正常操作误点击。
- 发布：以上都要在 Android / OriginOS 真机复核，无障碍权限本身无法保持开启是另一个独立问题。

## 7. 维护原则

**今后新增一个广告失败样本，优先问“它属于哪一类通用失败原因”，而不是问“这个 App 应该加什么特殊判断”。**

在通用语义规则、布局规则和回归样本都无法解释时，才考虑具体 App 或特定广告 SDK 的定向配置。
