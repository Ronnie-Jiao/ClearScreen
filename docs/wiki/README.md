## 1. 项目定位

净屏是一个以 Android 无障碍服务为核心的本地应用，用于在规则处于开启状态的应用中识别高置信度的“跳过广告”控件，以及带有明确广告语境的弹窗关闭控件。用户同意隐私政策、授权无障碍并打开总开关后才执行处理；应用规则默认开启，用户可单独关闭。

净屏 APP 备案状态正常，备案号为 `粤ICP备2026144630号-4A`，备案域名为 `clearscreen.cekoro.cn`。

当前应用名称是“净屏”，Android 技术包名是 `com.clearscreen.prototype`。包名、Release 签名和版本升级关系必须保持稳定，否则 Android 会把它当作新应用，原有授权和本地数据无法可靠衔接。

正式签名证书的公钥、证书指纹和公钥指纹见[净屏正式签名证书](签名证书.md)。该页面仅包含公开校验信息，不包含私钥或密码。

净屏不申请、不启动、不接管系统 VPN。网络过滤功能已经停用，用户可以同时使用自己的 VPN 客户端连接国外网络。

### iOS 广告处理

- Android 继续使用现有原生无障碍服务；iOS 主应用复用 React Native 页面基础组件和主题，平台入口按能力分流，不复用 Android 专属权限/应用管理流程。
- 当前已接入的 iOS 广告处理只有 `targets/safari/` 中的 Safari Web Extension；它仅作用于用户授权的网站，不跨 App 读取屏幕。网页内容仅在设备本地临时检查，不保存网址、页面文字、浏览历史或识别结果，也不上传。
- iOS 首页显示的“系统广告过滤”目前是目标能力展示，状态为“尚未接入”，不是有效的过滤开关。它不会拦截流量，也不应记作处理次数。
- 系统级 URL Filter 的目标最低版本为 iOS 26。Apple 说明该能力检查通过 WebKit 和 `URLSession` 发出的 HTTP/HTTPS 网址请求，按完整网址数据集作允许/拦截决定；它不识别屏幕、不点击广告关闭按钮，也不保证覆盖使用其他网络栈的 App。
- URL Filter 依赖设备端 Bloom 预过滤器和远程 PIR 网址数据库；潜在命中还要由 PIR 查询确认。准确率取决于广告网址数据集的质量，不能承诺所有 App/所有广告都能拦截。过滤数据不支持通配符或正则的默认匹配；需谨慎配置 URL 解析方式。
- 正式实现前必须补齐原生控制扩展、广告网址数据更新/Bloom 构建、PIR 与 Privacy Pass 服务配置、CloudKit Identity & Trust 注册、Network Extension entitlement/签名及苹果托管 OHTTP Relay 资格。缺任一项都不能将功能标记为“已开启”。
- Apple 官方资料：[URL filters](https://developer.apple.com/documentation/networkextension/url-filters)、[NEURLFilterManager](https://developer.apple.com/documentation/NetworkExtension/NEURLFilterManager)、[Filtering traffic by URL](https://developer.apple.com/documentation/NetworkExtension/filtering-traffic-by-url)、[WWDC25](https://developer.apple.com/videos/play/wwdc2025/234/)。
- 识别动作要求按钮文案明确写有广告跳过/关闭，或普通“跳过/关闭”控件与同一局部广告容器、广告标记及尺寸/边缘条件相符。不会点击取消、下载、购买或领取类按钮；不确定时不操作。
- 图片/Canvas 广告、嵌入框架中的广告、未提供明确可点击按钮的广告，以及网页结构不兼容的页面可能无法识别；Safari 扩展是保守的网页控件自动操作，不是完整的广告拦截器。
- Safari 扩展使用 `@bacons/apple-targets` 生成 iOS 原生扩展目标。更改 Expo target 配置后须重新 prebuild；iOS 真机构建、签名和 Safari 站点授权必须在 macOS/Xcode 与 iPhone 上完成。Windows 上的脚本/配置测试不代表已构建、签名或真机验收。
- 本地安全策略测试：`npm run test:safari`。iOS 隐私说明见[隐私政策](隐私政策.md)；公开隐私政策网站在更新并发布该说明前，不应宣称 iOS 版本可提交商店。

## 2. 工程结构

- `App.tsx`：React Native/Expo 应用入口、页面导航、总开关和权限引导。
- `src/screens/`：权限页、首页、应用列表、应用详情、记录详情、设置、服务与权限、排除应用页面。
- `src/native/ClearScreenNative.ts`：JavaScript 与 Android 原生模块之间的类型和状态适配。
- `src/screens/IOSSafariScreen.tsx`：复用既有 UI 基础组件的 iOS Safari 扩展引导页。
- `targets/safari/`：Safari Web Extension target 配置、广告控件判断和 Safari 扩展弹窗开关。
- `android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenNativeModule.kt`：原生状态、应用规则、无障碍状态和系统设置跳转。
- `android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenAccessibilityService.kt`：无障碍事件监听、广告控件识别和安全点击策略。
- `android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenStore.kt`：本地设置、应用规则和事件记录。
- `android/app/src/main/java/com/clearscreen/prototype/backend/ClearScreenPrivacyConsentStore.kt`：当前隐私政策版本和同意时间；在用户同意前不打开规则/记录存储。
- `src/screens/PrivacyPolicyScreen.tsx`、`src/privacy.ts`：首次同意、政策查看与公开政策版本/链接。
- [隐私政策](隐私政策.md)、[应用商店合规核查](应用商店合规核查.md)：对外处理说明和平台侧未完成事项。
- `android/app/src/main/res/xml/accessibility_service_config.xml`、`xml-v30/`、`xml-v31/`：无障碍服务声明；Android 11 及以上显式声明本地截图分析能力。
- `ACCESSIBILITY_PERSISTENCE_REPORT.md`：vivo/Android 无障碍授权保持问题的诊断记录。

### 界面导航与功能位置

- 底部一级导航为“首页 / 应用 / 设置”；处理记录从首页或应用详情进入，不占用底部导航位置。
- 首页根据无障碍授权、服务连接、应用启用情况和总开关显示当前状态及唯一主要操作，并展示今日真实处理数和最近记录。
- 应用页支持搜索、全部/已开启/已排除筛选；点击应用行进入详情，独立开关只控制该应用的自动跳过。
- 应用页右上角“全部开启”一次启用全部应用并清除其排除状态，不受搜索或筛选条件限制；执行后切回“全部”筛选。未保存规则的应用默认开启，后续新安装的应用同样默认开启。
- 关闭单个应用开关即排除，列表、详情、排除应用页及无障碍服务共用同一规则；重启、升级和列表刷新不会覆盖用户保存的关闭选择。旧安装的显式关闭规则继续保留，可点击“全部开启”主动恢复。
- 应用规则通过原生批量接口一次落盘；后台处理从同一规则存储读取，单应用关闭后也会停止其待执行识别与广告动作。全局总开关、隐私同意和系统无障碍授权仍独立生效。
- 应用详情提供该应用的单一启用开关和最近处理记录；记录列表作为二级页面提供全部、已执行和失败筛选及记录详情。
- 设置页以“服务与权限”单一入口进入二级页，子页提供自动跳过服务、后台运行，以及系统授权、服务连接和最近异常状态；设置页提供记录保留、清空记录、隐私政策、意见反馈、使用帮助、手动检查更新、诊断报告导出、APP备案号查询和版本信息。恢复默认只重置使用偏好并关闭总开关，保留应用排除规则、处理记录和记录保留周期。
- 外观设置目前不属于可访问的应用页面；未接通或未实现的旧控件不作为已实现功能展示。
- 首次启动先展示当前隐私政策；同意前不读取启动器应用列表、系统无障碍状态、旧规则/记录或其他应用界面。撤回时先停用本机处理，再删除规则、记录和设置；不替用户更改系统无障碍开关。
- Android 无障碍服务目前与主界面处于同一默认进程；`MainApplication` 中的独立进程保护仅在清单显式配置进程名时生效。隐私同意使用独立文件，并在服务每次处理前重新核验。
- Android 清单声明 `INTERNET` 权限，供用户主动检查 GitHub 公共发布信息；应用不会后台自动检查，查询不包含应用列表、处理记录或屏幕内容。截图与 OCR 结果不保存、不上传。Google ML Kit SDK 官方说明可能联系 Google 服务器获取组件更新/兼容信息并发送性能和使用指标。详见[隐私政策](隐私政策.md)。

## 3. 自动跳过和弹窗处理边界

### 3.0 识别安全原则（优先于覆盖率）

- “不误关”是所有规则的首要目标；任何截图或节点证据不足、互相矛盾、页面在扫描期间变化或点击目标不够独立时，必须放弃本次点击，不能为了多关广告而放宽全局阈值。
- 单独的 `X`/叉号、右上角位置、一个商业词或屏幕别处出现的“广告”都不是点击依据。广告线索、关闭图标和实际可点击节点必须能对应到同一个广告卡片或同一个弹窗子树；不允许把天气页中的推荐广告、会员区等线索拼给另一处悬浮 `X`。
- 彩云天气海报与 SDK 弹层保留两条结构窄规则。SVIP 海报规则要求同一父节点的 `entrance_image` 与 `close` 配对，目标居中、紧贴海报下沿且尺寸受限；新鲜 OCR 还必须在海报内识别 `SVIP`、年卡、会员、抽奖/奖品和“立即查看”。SDK 插屏只接受已核实的真实关闭控件 `cll_close_3`，并同时要求 `cll_interstitial_ad_gray`/`cll_gdt_ad_view`、明确“广告”标记和“跳转详情页/第三方应用”提示。SDK 的 `cll_close_click` 外观像叉号但实际会跳转到广告，已在候选筛选和执行前检查中硬性禁止；真实关闭控件未出现时不操作。
- 信息流卡片优先要求同卡片内有明确广告标记（如“推荐广告”），且 OCR 的小型 `X` 与一个可见、可点击、尺寸受限的无障碍节点重合并位于卡片边缘。OCR 只能帮助确认图标和文字，不能直接按坐标点击。没有明确广告标记时，必须在同一卡片内同时有至少三种不同商业线索和行动文案；单独的关闭图标不能触发。
- 彩云天气下载卡片另有一条例外：同一个有边界的卡片里必须同时读到“应用名称”、数值版本号、开发者、至少两项功能/权限/隐私/备案链接及“立即下载/抢先下载/安全下载”等明确下载文案，再与卡片右上边缘的独立小型关闭节点对应。此规则不扩展到商店、安装器或其他应用，不用页面其他卡片的隐私链接、会员文案或下载按钮补证据，也不点击下载按钮。
- 整页弹窗的文字/结构证据必须属于关闭按钮所在的浮层；覆盖整屏的通用根节点不能把页面其他区域的广告、会员或促销文案汇总成弹窗证据。截图 1 中脱离广告卡片的顶部 `X`，若无法从同一浮层节点或广告资源 ID 证实其归属，就保持不点；截图 2 的卡片 `X` 只在同卡片广告标记和独立可点击节点都确认后处理。
- 新增规则必须同时回归广告正例和相似的非广告负例（普通天气卡、会员/权益模块、业务弹窗、页面关闭按钮）；不能只用“广告成功关闭”作为验收。工程上采取保守失败关闭，但对未知应用仍不能宣称数学意义上的零误点或全覆盖。
- 系统权限、安装和应用跳转确认界面不执行广告动作；点击后若前台切换，记录为“结果未确认”，不能把目标控件消失等同于成功关闭广告。无文字的普通图片按钮仅靠控件类型和位置不能成为关闭候选。

### 3.1 会自动处理的控件

总开关开启、目标应用的“自动跳过”开启且应用不在白名单时，服务可能点击以下控件：

- 明确的广告跳过文字：`跳过广告`、`跳过此广告`、`跳过视频`、`Skip Ad` 等。
- 倒计时跳过文字：`3秒跳过`、`跳过3秒`、`3 Skip` 等还需广告专用资源 ID、同区域广告/视频证据，或顶部右上角位置加广告专用 ID；单独一个倒计时不触发。
- 资源 ID 包含 `ad_skip`/`skip_ad` 等明确广告动作时，可辅助识别小型可点击控件；普通 `skip`、`jump`、`countdown` 单独出现时不触发，必须补足同区域广告/视频证据。普通页面的 `xxx_jump` 不会仅凭命名触发。
- 普通“跳过/Skip”只有在同区域广告语境、经 OCR 验证的特定开屏广告，或最顶部右上角同时具备明确广告专用资源 ID 时才候选；纯位置兜底已移除，以免点击业务引导页。
- 通用开屏 OCR 补充：当应用只暴露普通“跳过”或倒计时标签时，必须是右上角紧凑控件、同屏存在大面积图片/视频创意，并且 OCR 读到明确广告标记，或读到至少两项促销线索和行动文案；截图与当前无障碍树必须匹配且足够新。屏幕角落、倒计时或促销词单独出现仍不触发。
- 对截图中的中国移动全屏广告样式，即使 SDK 没有把创意标记为 ImageView/WebView，也可用同屏左上角的小型明确“广告”徽标与下半屏完整“点击跳转详情页面/第三方应用”等提示联合验证。先用当前可访问节点文字（`builtin.skip.splash.labelled-redirect`），缺少节点文案时再用与当前树匹配的新鲜 OCR。必须没有可滚动页面内容，且当前右上角有小型真实可点击的跳过控件；单独的广告标记、跳过角标、页面促销文案或“免广告”不满足条件。
- 中国移动 `com.greenpoint.android.mc10086.activity` 的“55GB大流量卡 / 39元 + 40GB云盘”开屏另有精确图文组合：同屏 OCR 必须同时匹配套餐文字和下半屏“点击跳转详情页面”，候选须是右上角小型倒计时控件。1.0.41 起，若该应用没有暴露对应的无障碍跳过节点，还必须同时识别左上角广告标记、完整套餐组合及当前窗口/截图身份，才允许对 OCR 跳过文字的边界中心发送一次受限手势；不触碰广告正文或跳转按钮，手势完成只记为待确认。该规则不扩展到该应用其他页面或其他应用。
- 特定顶部居中的第三方跳转开屏广告：仅当 OCR 单词级边界能把“跳过”对应到顶部中央、宽高和面积都受限的独立可点击节点，并且同一张未过期、与当前整窗节点状态匹配的 OCR 截图同时含顶部“跳转第三方页面/应用”提示、下方“浏览器 + 看剧/追剧”文案和金币/惊喜促销动作时才处理；仅有居中“跳过”、单个促销词或位置相似的普通业务页不会触发。此规则不作为所有顶部居中控件的通用位置兜底。
- 视频广告的“跳过”：文字节点与可点击节点分别校验，点击目标必须较小且覆盖文字；“跳过视频”这类可能跳过正常内容的文案还需局部广告证据。普通内容变化短时重扫至约 1.8 秒，进入新窗口或出现广告候选时最多延长至 11 秒，并在候选仍存在时补采新 OCR；连续事件不会延长同一个任务的截止时间，切换窗口/应用或关闭应用规则后旧任务失效。检测到播放器刚出现或明确视频广告线索时，最长 45 秒以约 0.9 秒间隔继续检查延迟按钮，OCR 请求另有节流。按钮未启用或显示“几秒后可跳过/Skip in”的控件不提前点击；没有可访问按钮的强制观看广告不点击、不模拟快进。
- 具有本地广告标记或广告资源 ID 的弹窗关闭控件，例如“关闭广告”、广告关闭叉号和 `ad_close`、`close_ad`、`adclose` 等资源。
- 整页遮罩广告：当可访问节点同时呈现广告强标记、多个商业/营销词、较大的遮罩或广告面板，并在右上角暴露紧凑的“关闭”/`X`/图标控件时，使用独立的全屏广告规则关闭它；无文字的 `ImageView` 关闭图标也只在这一组证据同时成立时处理。较大的“面板”必须是弹窗/广告类浮层（类名或资源 ID 含 popup/dialog/overlay/splash/ad 等），页面自身的列表和滚动容器不算遮罩。
- 通用弹窗 OCR 补充：如果应用没有把弹窗容器标成 popup/dialog，仍可在一个有边界、非列表滚动的局部父容器里判断；该容器必须同时包含“广告/推广”等标记和行动文案，或至少三项不同促销线索及行动文案。关闭目标必须是可独立点击的小控件、贴近该容器上边或侧边，OCR 的叉号与控件位置重合；不能从页面其他区域借广告证据，也不能按坐标点击。
- 彩云天气 SVIP 海报弹层的中下部无文字 `X`：仅对已核实的包名及 `entrance_image`/`close` 资源 ID 生效；关闭节点必须是小型可点击 `ImageView`，与大海报共用无障碍父节点、水平居中并紧邻海报下沿；本地 OCR 必须在海报范围内同时识别到 SVIP、年卡、会员、抽奖/奖品、“立即查看”及至少三种商业线索。命中规则 ID：`builtin.popup.close.centered-poster`。其他应用或页面结构不满足时仍保持不点。
- 彩云天气 SDK 插屏底部无文字 `X`：仅在包名为 `com.nowcasting.activity` 时，匹配可点击 `cll_close_3`、同一无障碍树中的 `cll_interstitial_ad_gray` 与 `cll_gdt_ad_view`，并从同一插屏窗口读到资源 ID `cll_ad_tips` 的“广告”及 `cll_ad_tip_title` 中“跳转详情页/第三方应用”提示；目标必须是水平居中、贴近该弹窗窗口底边且尺寸受限的 `ImageView`。命中规则 ID：`builtin.popup.close.caiyun-interstitial.bottom-center`。SDK 的 `cll_close_click` 是广告点击入口，已被全候选路径和执行前校验硬性排除；若真实关闭控件尚未显示则不操作。其他结构、文案、位置不符时也不点击。
- 中国移动“广东移动视频号福利 / 5GB”轮播海报：仅对 `com.greenpoint.android.mc10086.activity` 的该组合使用 `builtin.popup.close.mobile-campaign-carousel`。同一非滚动、无输入框的容器里，必须有尺寸受限的居中海报、海报内的广东移动/视频号/福利/5GB/立即前往及限量文案、下方成对的“上一条/下一条”，再关联海报右上方的独立可点击关闭节点。关闭语义仍由文字、资源 ID 或小型 X 图形验证，不能只借页面上的营销词、别处广告标记或位置触发。
- 播放器暂停广告、页面内嵌广告卡片：新增通用窄规则 `builtin.popup.close.embedded-ad-card`。同一无障碍子树中须有小型明确广告徽标和直接可点击的独立关闭节点；普通 X/关闭须位于该卡片右上边缘，底部居中只接受“关闭广告”文字或广告关闭资源 ID。卡片与控件尺寸均受限，不能把相邻内容的广告徽标拼给无关 X。它只覆盖符合这些结构的页面，尚未针对具体影视 App 实机验收。
- 广告强标记排除否定说法：`免广告`、`无广告`、`去广告`、`屏蔽广告`、`拦截广告` 等只表示“没有广告”，不再被当作广告证据，避免把普通个人主页（含“免广告”文案和 VIP/会员入口）误判成整页广告。注意 `关闭广告`、`跳过广告` 是控件自身的文字，仍算广告线索。

- 信息流/瀑布流广告：Android 11 及以上使用系统无障碍截图和本地中文 OCR，把同卡片的“广告/推广/赞助”等标记或“至少三项不同商业词 + 行动按钮”与小型关闭控件关联。若无障碍树本身同时暴露明确广告徽标和直接可点击的关闭节点，也可走内嵌广告卡片规则。无标签图片控件只有资源 ID 表明关闭，或 OCR 小型 X 与实际可点击节点重合时才候选；只凭图片控件类型不再点击。广告证据不足、卡片边界不清或点击目标过大时跳过；关闭后重新扫描列表。
- 中国移动消息页可能把“话费账单提醒”“卡券到账提醒”“专属提醒不错过”作为普通通知文案。1.0.44 只对这三条固定提示取消“提醒”类保护误判；卡片仍须在同一局部 OCR 区域同时匹配广告标记和小型可点击 X，其他时间敏感文字、窗口和控件保护不变。
- 彩云天气已见的应用下载卡片可走 `builtin.feed.close.download-disclosure`：本地 OCR/节点文字在同一卡片内满足应用名称、数值版本、开发者、至少两项合规链接和明确下载文案，且卡片右上角有尺寸受限、真实可点击的关闭控件。正常天气图表、SVIP 解锁区和仅有隐私/版本信息的页面不满足条件。非滚动的局部 WebView 可以作为卡片容器；真正的滚动容器仍排除。该规则的例外包名仅为 `com.nowcasting.activity`。
- 原生存储仍保留开屏/视频、弹窗和信息流分类开关以兼容已有安装；当前界面不提供分类开关。未保存过的分类设置默认开启，旧值保留；处理仍受总开关和单应用规则约束。

### 3.2 本地截图/OCR 的能力边界

- 1.0.32 将完整屏幕截图按物理显示尺寸映射，OCR 文本必须落在当前应用窗口内。1.0.39 保留窗口 ID、包名、根区域和显示尺寸校验，将文字一致性限制在实际使用证据的广告容器及控件子树；比较节点身份、资源 ID、类型、位置、标签和可操作状态，拒绝已替换或移动的局部区域。已可跳过的“2 跳过 → 1 跳过 → 跳过”只规范化计数，不忽略“几秒后可跳过”或业务引导文字；容器外天气刷新不再让广告证据全部作废。开屏使用整窗证据，因此仍检查整窗的规范化节点状态。执行前若页面有变化，重新识别并要求仍为同一节点、同一规则和同一位置，最后刷新真实目标的当前状态。
- 短时倒计时期间，紧凑可点击跳过控件内的数字及可用状态切换不会单独使 OCR 窗口证据失效；一般候选识别和执行前仍基于最新无障碍节点，目标未启用时不点击。唯一例外是上方列出的中国移动 55GB 开屏：仅当无障碍树没有对应跳过节点且精确 OCR 组合完整时，才对当前 OCR 文字边界中心发送手势。
- 中国移动该开屏的窗口切换事件会优先触发截图 OCR，不受通用 OCR 间隔限制；只对这个包名缩小输入图像以减少识别耗时。该规则使用同包、同窗口、1.8 秒内的截图校验，不要求整棵无障碍节点树保持不变，以容忍倒计时节点变化；套餐组合、广告标记、跳转提示和右上跳过文字都要同时吻合。Android 11 及以上的服务资源配置都声明了可发送手势，避免系统版本限定资源覆盖基础配置。
- 小型 X 同时从逐字 OCR 元素、整行结果和本地图形分析提取。`AdCloseIconDetector.kt` 只对截图前已暴露的独立小型可点击控件采样，对比四条对角笔画、中心和间隙背景，排除圆环、加号及单侧箭头；每帧最多 40 个候选。图形结果只辅助确认关闭语义，不产生点击坐标、不代替局部广告证据，也不能越过已知假叉号拦截。节点正文与无障碍描述分别匹配；字体宽窄字符和不可见分隔符统一规范化。
- 1.0.32 在执行广告控件动作后最多再检查两次，覆盖关闭弹窗后出现信息流卡片、同一广告结束页没有发出新事件，以及系统接受点击但实际未生效的情况。成功统计同时检查原控件是否仍可刷新且可见；仅因旧 OCR 过期或不再命中规则，不会直接计为关闭成功。每次后续识别/动作仍重新检查隐私同意、前台应用及应用规则。
- 1.0.18 起使用 APK 内置的中文 OCR 模型；Android 11 及以上通过无障碍截图在本机内存中分析文字，不保存截图或识别文字。Google ML Kit 可能联系 Google 服务器获取组件更新/兼容信息并发送性能和使用指标，详见[隐私政策](隐私政策.md)。净屏自身不上传截图、OCR 结果，不调用 VPN 或云端识别。自 2026-10-16 起，Android 清单声明 `INTERNET` 权限，仅由用户主动检查 GitHub 公共发布信息；不会后台自动检查，也不发送应用列表、处理记录或屏幕内容。1.0.19–1.0.24 加入卡片内 OCR X、顶部居中广告文案、彩云天气两类已取证插屏的局部证据。1.0.25 把可点击节点、广告徽标和卡片归属按准确的无障碍子树关联，收紧泛用 X 与 `jump` 的误点条件；在明确播放器场景中有限时地等待延迟出现的跳过按钮。1.0.26 增加与应用包名无关的全屏创意/促销组合判断，以及对没有标准弹窗类名的局部容器 OCR 兜底，仍要求证据局部对应和真实独立点击控件。1.0.39 起按上述局部节点身份与状态校验 OCR，窗口或广告证据区域失配时拒绝，并最多补采一次新截图。检测到密码字段或正聚焦的文本输入框时，不启动截图 OCR。Android 10 及以下、系统拒绝截图、受保护窗口，以及系统/游戏/网页 `Canvas` 未暴露可访问关闭控件时，回退到原有无障碍节点规则。
- 这是“本地 OCR + UI 结构/位置规则融合”，不是针对各应用广告训练的专用视觉模型。仓库没有广告训练数据集或专用分类模型，不能承诺所有广告都识别或零误点；页面文案、卡片层级与控件可访问性都会影响结果。
- 只有 OCR 文本证据、却没有可访问且可点击的独立关闭节点时，通常不会使用屏幕位置触发动作；唯一例外为上述中国移动专用开屏。该例外使用新鲜 OCR 文本本身的边界中心，并同时验证限定包名、广告标记、完整套餐文案、跳转提示、窗口身份与右上角紧凑倒计时；不形成面向其他页面的通用坐标点击能力。其他应用、其他创意以及截图被保护或当前窗口不匹配时仍保持不操作。

### 3.3 明确不会自动处理的内容

- 普通业务按钮：`确定`、`允许`、`授权`、`下一步`、`领取`、`打开`、`下载` 等。
- 没有可访问节点或没有可点击动作的图片、Canvas、视频内嵌控件。
- 仅靠截图看起来像 X、但无障碍树中不存在独立可点击控件的关闭图标。
- 没有广告标记的普通“关闭”、返回按钮或叉号。
- 只有系统 `ACTION_DISMISS`、没有明确关闭控件的原生 Dialog。
- 仅因为屏幕其他位置出现“会员”“福利”“促销”等商业文字的弹窗。
- 净屏自己的页面。服务会跳过自己的包名，避免把“今日自动跳过”等页面文字当成广告控件。

服务只执行实际的 `ACTION_CLICK`，不再使用通用 `ACTION_DISMISS` 作为兜底关闭动作。为了避免误关业务弹窗，个别没有可访问广告标记的广告可能不会被处理，这是有意的安全取舍。

### 3.4 关闭条件

以下任一条件成立时，服务不会执行广告动作：

- 总开关关闭。
- 目标应用规则关闭自动跳过。
- 目标应用加入白名单。
- 对应类别开关关闭（旧设置仍保留；当前界面不提供该项设置）。
- 无障碍服务没有被系统授权或没有完成绑定。
- 控件不可见、禁用、没有可点击父节点或没有有效屏幕位置。

## 4. Android 和 vivo 权限

### 4.1 用户必须手动授权

普通第三方应用不能静默打开无障碍，也不能通过代码修改系统安全设置。首次使用需要：

1. 在净屏权限页点击“自动跳过权限”。
2. 进入系统无障碍设置，手动打开净屏服务。
3. 在系统确认框中点击允许。
4. 返回净屏，确认状态从“启动中”变为“已开启”。

### 4.2 Android 受限设置

通过 USB、本地文件或其他旁加载方式安装时，Android 可能限制敏感无障碍服务。遇到服务开关无法保持开启时：

1. 打开“应用信息”。
2. 打开右上角菜单中的“允许受限设置”（如果系统提供）。
3. 返回无障碍设置重新开启净屏。
4. 如果系统没有这个入口，使用可信应用商店或 vivo 官方互传重新安装。

### 4.3 vivo/iQOO 后台保护

如果 vivo 返回设置列表后把服务改成“已关闭”，这通常是系统的自启动或后台限制，不是应用身份字段问题。请在系统设置中：

- 允许净屏自启动；
- 允许后台运行或后台耗电；
- 关闭对净屏的电池优化/智能冻结；
- 必要时在最近任务中锁定净屏。

应用只能引导用户打开这些页面，不能代替用户修改厂商开关。

## 5. APK 构建与安装约定

### 5.1 默认安装方式：USB 数据线

以后普通 APK 安装默认通过 USB 数据线完成，不再要求使用网页版“互传”：

1. 在电脑上生成并核对正式签名的 Release APK。
2. 用数据线连接目标手机，在手机上允许 USB 调试授权；执行 `adb devices -l`，只对状态为 `device` 的目标序列号操作。
3. 用 `adb -s <设备序列号> install -r <Release APK 路径>` 升级安装。两台手机分别安装，不使用卸载或清除数据命令。
4. 安装后按设备核对 `com.clearscreen.prototype` 的 `versionCode`/`versionName`，再检查无障碍服务是否仍启用；安装成功不等于系统授权或广告识别已经验收。

如果系统对 USB 侧载应用限制无障碍服务，按第 4.2 节处理；可信应用商店或厂商互传只是该问题的备选安装来源，不再是日常默认流程。

升级已有净屏时使用升级安装，不要先卸载旧版，也不要清除应用数据。必须保持包名 `com.clearscreen.prototype` 和同一 Release 签名，这样才能保留无障碍授权、应用规则、白名单和记录。

## 8. 变更记录

项目逐次修改的时间线见[净屏修改记录](CHANGELOG.md)。本节保留概要，细节以修改记录为准。

### 2026-10-10

- 日常 APK 安装改为默认使用 USB 数据线和 `adb install -r`；网页版互传不再是固定规则。

### 2026-09-22

- 收紧广告弹窗识别：普通 `ACTION_DISMISS` 不再作为关闭兜底。
- 普通关闭按钮不再使用全屏商业文字作为广告依据。
- 增加整页遮罩广告规则：要求广告强标记、营销词簇、较大遮罩/广告面板和右上角紧凑关闭控件共同成立，兼容无文字的关闭图标并保持普通业务弹窗保护。
- 增强视频广告“跳过”识别：分离文字节点和可点击父节点的几何判断，并增加动态加载短时重试与 `builtin.skip.video-ad.edge` 诊断规则。
- 移除 ClearScreen 的 VPN Service、VPN 权限和网络过滤入口，避免抢占用户自己的 VPN。
- 当时曾约定通过网页版互传发送 APK；该安装约定已于 2026-10-10 废止。
