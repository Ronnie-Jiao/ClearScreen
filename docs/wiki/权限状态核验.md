# 权限状态核验

最近核对：2026-10-22。仅说明源码实现及只读接口证据，不代表新 APK 已安装或真机功能已验收。

## 状态与来源

| 项目 | 来源 | 明确状态 | 无法读取 |
| --- | --- | --- | --- |
| 系统授权 | Android 无障碍启用列表中的净屏组件 | 已授权 / 未授权 | 整体调用失败显示核验失败 |
| 服务连接 | Android 服务列表与净屏服务自身运行标记 | 已连接 / 未连接 | 同上 |
| 自启动（vivo/iQOO） | 本应用权限管理记录的 `currentstate` | 0 = 已开启，1 = 未开启 | 需手动确认 |
| 自启动（小米/Redmi/POCO） | 系统允许访问时的 `getApplicationAutoStart`，否则只读页面核验 | 0 = 已开启，1 = 未开启 | 需手动确认 |
| 自启动/后台活动（其他已登记品牌） | 用户主动进入系统设置后，只读本应用的明确可勾选控件 | 已开启/未开启，已允许/未允许 | 需手动确认；不宣称所有版本可读取 |
| 后台运行 | `ActivityManager.isBackgroundRestricted()` | true = 受限制，false = 未受限 | 需手动确认 |
| 电池优化 | `PowerManager.isIgnoringBatteryOptimizations(packageName)` | true = 已忽略，false = 未忽略 | 读取失败 |

“未受限”只表示 Android 标准后台限制未开启，不等于厂商后台耗电、冻结、自启动和任务锁定均已放行。标准限制明确为 true 时始终优先显示“受限制”，不被页面核验的允许值覆盖。vivo 读取的是系统“自启动”管理中的后台启动允许项，不表示净屏申请了开机广播或能自行开启系统服务。

## 只读设置页核验的条件

1. 只在用户从净屏主动打开自启动或后台设置后启动，最多 3 分钟；仅接受当前品牌已登记包及 `com.android.settings`，还须由系统应用标记确认不是冒名的普通 APK。
2. 必须找到净屏自身包名；只能按名称定位时，先核对可启动应用中没有同名的其他包，并拒绝当前页面的重复身份。未读取图标，不把另一应用的开关借给净屏。
3. 全局自启动列表须有明确正向标题，开关与净屏标签位于同一小型行、垂直范围吻合且唯一。华为“自动管理”、关联启动、三星休眠/深度休眠列表等不映射成自启动允许。
4. 详情页须在自身身份下定位明确的自启动/后台活动字段；局部节点超过预算、多个匹配控件、不可用控件、Android 16 混合勾选状态、密码/聚焦输入等均拒绝。电池页只接受明确已选中的受限/无限制项，不按未选中或普通“优化”猜测。
5. 同一窗口至少两次间隔 100ms 的一致结果才采纳。监听只做读取，没有点击、手势或系统写入；不启动 OCR，不保存/上传页面文字和节点。
6. 返回后只在本机内存保留本次结果；下一次离开前台、服务解绑/销毁、撤回同意或 5 分钟后失效。未开启无障碍时，这条兜底不可用；系统 API 查询不受此限制。此能力不能在未访问对应设置页面时读取厂商私有开关。

实现来源与限制：小米接口选择器及 0/1 含义参考作者的 [MIUI-Autostart 源码](https://github.com/XomaDev/MIUI-Autostart/blob/master/library/src/main/kotlin/xyz/kumaraswamy/autostart/Autostart.kt)，没有引入库、隐藏 API 解禁、`setAccessible` 或其“未知默认 true”逻辑。Android 明确说明[非 SDK 接口可能受限制](https://developer.android.com/guide/app-compatibility/restrictions-non-sdk-interfaces)，限制出现时保留未知，不绕过。只读控件基于 [Android 无障碍服务](https://developer.android.com/guide/topics/ui/accessibility/service)；新 Nokia 入口复用 [AutoStarter 的候选标识](https://github.com/judemanutd/AutoStarter/blob/master/autostarter/src/main/java/com/judemanutd/autostarter/AutoStartPermissionHelper.kt)，并非本项目的全版本实测结论。

- 清单中 `PermissionProvider` 已导出，authority 为 `com.vivo.permissionmanager.provider.permission`；声明写权限，不要求调用者持有额外读权限。REA Evidence：`ev_0bbbd4111a622b6560ceac9025d6b1bef15c8181b1ca807c12ddd4b753736de5`。

- `StartupPermManager` 的另一组 `bring_up_other_apps` 记录属于受权限保护的 appfilter provider；调试 shell 读取被系统拒绝，未尝试绕过，也未将其加入实现。旧 provider 对调试 shell 的空结果不能证明净屏自己的记录不存在，因为调用者包名不同。

这些是当前系统组件的静态证据，不承诺其他 OriginOS 版本或所有品牌均开放读取。没有记录、未知值、UID 不符、重复记录、拒绝访问或超时均返回未知，绝不按已开启处理。

## 刷新与边界

- 进入权限页、从任意系统设置返回前台均重新读取。设置返回后保留短延时复核，等待开关落盘或服务绑定。
- 权限接口使用独立原生线程；vivo 查询复用单个在途任务、等待上限 1.2 秒，前端单次读取 4 秒超时。失败明确结束核验，不因完整应用列表加载长时间显示“核验中”。
- 后续应用列表/处理记录刷新不覆盖更新的权限快照。离开前台或发起另一设置跳转后，旧结果不应用；撤回隐私同意后也丢弃旧结果。
- 不新申请权限，不使用隐藏 API 解禁、root、ADB 运行时依赖或系统设置自动点击；不保存或上传厂商权限记录。系统设置始终从广告动作路径提前返回，只允许上述独立、限时的只读核验；总开关暂停时可以核验自己的权限，但不会处理广告或点击设置。
- 仅进行了 TypeScript、Android Kotlin 编译和清单静态检查；未运行自动化功能测试，未启动应用验收，未打包或安装。仍需用户在显式请求打包后检查开关开/关及返回状态。
